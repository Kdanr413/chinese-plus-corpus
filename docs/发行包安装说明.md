# 从 GitHub 安装与迁移

个人电脑和服务器均使用同一 GitHub 源码。路径相对于包含 configs/pipeline.json 的项目根目录。第一次需要安装 Git、Conda、PostgreSQL；源码 ZIP 是 GitHub 源码的离线副本，不内置 Python、话题依赖或模型。

## 1. 获得源码及 Python 环境

在自己选择的目录执行（私有仓库需要先获得访问授权）：

```powershell
git clone https://github.com/Kdanr413/chinese-plus-corpus.git
cd chinese-plus-corpus
conda env create -f environment.yml
conda activate corpus-platform
```

当前完整验收使用 Windows x64、Python 3.11。首次依赖安装需联网，有些机器可能需要本机构建工具。模型首次下载较大：

```powershell
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-zh-v1.5')"
```

模型默认在当前用户的 Hugging Face 缓存目录；不随源码迁移。安装失败时先保留命令窗口错误，修复后重新安装，不能直接开始话题构建。

## 2. 创建自己的数据库

启动 PostgreSQL。在 SQL Shell（psql）使用安装时设置的 postgres 管理员账号登录，确认主机和端口。在 SQL 中把密码占位文字替换成自己的数据库密码：

```sql
CREATE USER corpus_user WITH PASSWORD '替换为你自己的数据库密码';
CREATE DATABASE corpus_platform OWNER corpus_user;
```

数据库与用户已存在时不用重复创建。这不是网页登录账号。项目用户需由该数据库角色创建 schema，因此 corpus_user 应是 corpus_platform 数据库的所有者。

在源码根目录执行：

```powershell
Copy-Item .env.example .env
notepad .env
```

已有 .env 不要覆盖。填写：

```dotenv
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=corpus_platform
DB_USER=corpus_user
DB_PASSWORD=填写自己的数据库密码
CORPUS_DATA_ROOT=data
PORTAL_STORAGE=data/portal
PORTAL_TEMPLATE=portal_template
TOPIC_WORKFLOW_PYTHON=
API_HOST=127.0.0.1
API_PORT=8000
PORTAL_PUBLIC_URL=http://127.0.0.1:8000
```

含 # 或空格的值可加英文双引号。相对数据路径自动以项目根目录解析。不要复制别人电脑上的 Python 路径；话题依赖安装在当前环境时通常留空，另用专门环境时必须由本机管理员配置实际可执行程序。

## 3. 建表、账号和启动

```powershell
python -m corpus_registry init-db
python -m corpus_platform serve --setup
```

第一条为已存在数据库建程序表，不安装 PostgreSQL、不创建数据库。第二条首次在终端创建网页登录账号；密码至少 3 字符，输入不显示。访问 http://127.0.0.1:8000/，登录并创建项目。后续 `python -m corpus_platform serve`；Windows 安装环境后可双击主启动器。使用期间不能关闭服务窗口。

```powershell
python -m corpus_platform portal add-user user02
python -m corpus_platform portal reset-password user02
python -m corpus_platform doctor
```

按实际需要执行。网页不开放自助注册。遇到数据库连接错误检查服务、账号密码和端口；端口被占用先检查已有进程，再调整 API_PORT 和 PORTAL_PUBLIC_URL 为一致地址。

## 4. 构建接口与分享入口

上传 TXT 或只含 TXT 的 ZIP；参考话题用 [JSON 模板](../参考文件中心/模板/参考话题体系.json) 和 [字段说明](../参考文件中心/话题体系格式说明.md)。

话题审核接口需要真实服务和密钥，PORTAL_LLM_ALLOWED_HOSTS 由主机管理员允许实际 HTTPS 域名；真实句法在用户项目 configs/pipeline.json 的 syntax_tree 中配置可用 base_url/endpoint。预设服务地址不保证在新电脑网络中可用；合成测试语法不能用于正式研究。

个人电脑或服务器想让他人检索，都须提供他人可访问的网络入口。完成第 6 步后生成只读分享链接。公网配置及长期运行见 [部署说明](../deploy/portal/README.md)，不要把 127.0.0.1 链接发给远程接收者。

## 5. 迁移与升级

停止任务，备份 PostgreSQL、.env 和 data/portal/projects。新主机重新 git clone、安装依赖和模型，恢复项目与数据库，再填写新主机配置。不是复制旧 Python 环境。自己填写过的绝对路径和历史任务中的路径需要管理员检查；项目编号、数据目录和版本资产要保持对应。

更新前备份，再 git pull --ff-only；按变更更新依赖。新模板只影响新项目，已有项目内的代码不会随主仓库自动升级。详见 [主说明](../README.md) 及 [多用户说明](../corpus_portal/README.md)。
