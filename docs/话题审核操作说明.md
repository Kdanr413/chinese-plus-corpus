# 话题体系人工审核

当前人工审核在网页的话题体系弹窗中完成，不需要下载旧版 `taxonomy_review_workbench.csv`。

## 审核对象

系统先从全量有效句子/话轮固定抽取 `ceil(N/3)`，产生候选话题并让多个模型独立判断。人工只处理新话题、模型冲突、层级冲突或边界不清的项目。

## 每项至少检查

1. 名称是否清楚，是否描述领域内容而不是文体、来源或情绪；
2. 一级、二级、三级的父子关系是否合理；
3. 定义能否覆盖代表句子，又不会过宽；
4. 是否与已有话题重复，应合并还是保留；
5. 模型给出的原句证据是否真的支持该话题。

## 可做的决定

- 接受现有节点或模型建议；
- 修改名称、定义或父节点；
- 新增话题；
- 合并重复话题；
- 拒绝不属于话题体系的候选。

人工决定必须保留操作者、时间、原值和修改后值，不能覆盖机器原始意见。

## 发布结果

完成冲突裁决后点击发布。正式体系写入：

```text
data/curated/topics/taxonomy.json
```

主流程随后使用这套体系标注全量句子或完整话轮。弹窗中的临时候选和聚类 ID 不能直接当作正式话题 ID。


## 查看批量审核结果

打开话题工作台，选择对应轮次，进入“多模型独立审核”。在“模型结果查看与下载”点击“查看逐聚类判断”，可查看每簇分类路径、理由、体系修改或失败原因；同一区域可下载 CSV 和 JSONL。测试首个聚类不会保存批量结果。成功记录与失败记录均保存在该项目 data/workspaces/chinese-plus/topic-workflow/workflow/rounds/轮次/models/模型/annotations.jsonl；attempts.jsonl 是调用记录，working_taxonomy.json 是该模型的体系分支，checkpoint.json 是进度检查点。不要将模型私有分支当作已正式发布体系。
