# 中文+语料库：完整构建与共享流程

个人电脑和服务器使用同一套源码，统一从 GitHub 拉取。平台提供登录、独立用户项目、语料上传、六步构建、版本发布和只读分享。所有文件路径都相对于项目根目录；源码不包含原始语料、账号数据库、密钥、Python 运行环境或模型缓存。

模型标注中间结果保存在各项目的 `data/model_annotations/`，后续轮次自动复用相同模型、接口、提示词和实际输入的已保存结果，减少重复调用。文档或段落编号变化不会阻止复用；语句、上下文、参考体系、候选输入或模型版本变化时重新标注。新一轮清洗前会归档旧任务和模型回复，各用户项目的缓存相互独立，缓存不随源码上传 GitHub。详见 [步骤模型配置与项目命名](docs/步骤模型配置与项目命名.md)。

模型批处理遇到单项超时、接口错误或无效输出时记录错误并继续其余条目，不把失败当作成功标注。各项目 `data/model_errors/` 保留失败请求与重跑记录；加工页侧栏“模型失败条目 / 重跑”可选择条目重跑，话题分支也提供“重跑失败项 / 继续运行”。重跑请求成功后，由原流程断点续跑校验并合并。清洗输出使用 Windows 扩展路径进行磁盘读写，完整标题仍保留，已实测超过 280 字符的路径写入。

句法树步骤会逐片段保存回复与缓存，页面提供“仅续跑句法步骤（复用成功片段）”入口。单条失败留痕，连续服务失败会停止等待处理；临时进度查询超时会自动重连。文件位置、失败重试与命令行操作见 [统一加工流程与操作台](docs/统一加工流程与操作台.md#句法树的中断结果保存与续跑)。

最终领域术语表下载包含基础提取得分 `score` 及来源说明；历史漏分表会从该轮次已保存明细补齐，无需重新识别。得分含义见 [术语识别与人工验证指导](docs/术语识别与人工验证指导.md#最终术语表的得分列)。

检索页默认展示前十领域术语，并提供当前筛选范围的完整频次 CSV；例句展示话题名称，标志词在体系详情中查看。基础语料上传区每批选择来源后点击“上传本批语料”；教材按每个 TXT 文件名（不含扩展名）登记书名，ZIP 内也逐文件登记。已有文档可批量补录。跨电脑访问、只读分享 API 和正式话题体系复用见 [跨电脑共享与只读 API](docs/跨电脑共享与只读API.md)。

## 公开检索与构建流程下载

如果只希望访客查询已有语料、了解流程并下载程序到本地构建，使用独立公开站：与构建平台共用源码，入口和进程分开。它提供首页、流程、完整源码下载、模板与只读 API，没有在线上传加工入口。私有构建平台默认 8000，公开站默认 8002；原有项目与发布版继续保留。

```powershell
python -m corpus_platform public-site --config configs/public_site.example.json
```

打开 http://127.0.0.1:8002/。示例尚未选定公开数据或下载包；实际配置应存入私有 `data/public_site/settings.json`，只列出愿意公开的正式发布版本。公众可从网站直接下载脱敏完整源码 ZIP；GitHub 仓库当前保持私有。完整操作与文件清单见 [公开展示与只读检索网站](docs/公开展示与只读检索网站.md)，服务器入口见 [公开站部署](deploy/public/README.md)。只读服务器可安装 `requirements-public.txt`，不需要 PostgreSQL 服务或模型；个人构建仍按下文安装完整环境。

## 拉取与安装

仓库保持私有，需要登录已获得仓库授权的 GitHub 账号。安装 Git、Conda 和 PostgreSQL，然后在你选择的目录执行：

```powershell
git clone https://github.com/Kdanr413/chinese-plus-corpus.git
cd chinese-plus-corpus
conda env create -f environment.yml
conda activate corpus-platform
Copy-Item .env.example .env
```

首次完整安装请按 [安装与迁移说明](docs/发行包安装说明.md) 创建自己的数据库并填写 `.env`。已有 `.env` 时不要覆盖。准备话题模型及程序表：

```powershell
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-zh-v1.5')"
python -m corpus_registry init-db
python -m corpus_platform serve --setup
```

首次在终端创建登录账号，密码至少 3 字符；打开 http://127.0.0.1:8000/。后续启动执行 `python -m corpus_platform serve`，Windows 也可在环境安装后双击 `启动语料库平台.cmd`。使用期间保持服务运行。

目前完整构建与 BCC 原生检索验收使用 Windows x64、Python 3.11。服务器优先使用同架构 Windows；Linux/Docker 文件保留供后续验证，尚不能承诺完整原生索引链路直接运行。安装模型依赖后，仍需配置实际可用的话题审核接口和真实句法服务；不得把测试合成语法当作正式成果。

## 个人电脑与服务器

个人电脑：默认仅本机访问。要分享给其他电脑，配置对方能访问的主机地址或域名，并使服务保持在线。

服务器：仍按上述方式 git clone 和安装，在 [服务器部署说明](deploy/portal/README.md) 中完成公网入口、HTTPS、数据库和常驻运行设置。用户登录后独立创建项目，在网页上传原文并完成构建。不要把项目文件夹配置为公开静态网站。

## 上传与构建

登录 → 创建项目 → 上传 TXT 或只含 TXT 的 ZIP → 按六步构建 → 发布和建立索引。需要人工审核时，按工作台提示完成审核后继续。

人工参考话题体系使用 UTF-8 层级 JSON：

- [最小上传模板](参考文件中心/模板/参考话题体系.json)
- [完整填写示例](参考文件中心/模板/参考话题体系_填写示例.json)
- [字段说明与上传位置](参考文件中心/话题体系格式说明.md)

其他上传模板见 [参考文件中心](参考文件中心/README.md)。网页资源区可取得对应模板。只在自己的项目中上传，不通过修改全局配置代替上传。

## 两种分享方式

**在线链接**：第 6 步选择已建立索引的正式版本，生成只读分享链接，发给他人直接检索。可设置期限或撤销；接收者不需要 GitHub、安装代码或构建账号。主机、门户、数据库和版本资产需持续可用。个人电脑与服务器都支持这一方式，个人电脑也必须提供可访问网络入口；localhost 链接无法供远程访问。

**完整成果导出**：导出一个完整已发布的 Release，让另一台主机从同一 GitHub 拉取源码后运行独立只读检索服务。详见 [成果导出与独立检索](corpus_delivery/README.md)。独立检索不需要账号数据库；它没有门户分享链接的授权、过期和撤销功能。

## 保存位置与备份

| 内容 | 相对路径 |
| --- | --- |
| 用户项目 | `data/portal/projects/<项目编号>/` |
| 项目上传原件 | `data/portal/projects/<项目编号>/data/raw/manual/` |
| 项目参考文件原件 | `data/portal/projects/<项目编号>/data/raw/reference_uploads/` |
| 项目过程与轮次 | `data/portal/projects/<项目编号>/data/workspaces/` |
| 项目正式版本及索引 | `data/portal/projects/<项目编号>/data/releases/` |
| 新项目的干净程序模板 | `portal_template/` |

账号、会话、项目归属与分享授权在 PostgreSQL；主机配置在 `.env`。不同用户项目独立存储。备份需同时包含项目、数据库和配置；源码 ZIP 不代替数据备份。原始语料与正式版本必须保护，日常更新不得删除 `data/raw/` 或任何用户项目中的原件。

## 更新和维护

停止构建任务后备份数据与配置，再在源码目录执行 `git pull --ff-only`，按变更说明更新依赖。不要用清理 Git 工作区的命令删除本机配置或数据。新项目使用新模板；已创建项目自带代码副本，更新主仓库不会自动升级这些项目，需管理员备份后安排单独升级。

管理员新增或重置账号：`python -m corpus_platform portal add-user user02`、`python -m corpus_platform portal reset-password user02`。检查：`python -m corpus_platform doctor`；回归方法见 [测试说明](tests/README.md)。

最终交付只有一份完整源码 ZIP及校验记录，与 GitHub 默认分支源码一致，不再分发三套程序或附带核心便携环境。发行维护见 [维护说明](scripts/maintenance/README.md)。第三方许可证见 [第三方声明](THIRD_PARTY_NOTICES.md)，完整多用户说明见 [多用户功能](corpus_portal/README.md)。

步骤模型选择、保存与测试，以及同账号项目名称查重，见 [操作说明](docs/步骤模型配置与项目命名.md)。清洗选择一个明确模型；术语与交叉检验分别选择自己的模型组。


### 更换或移除参考话题体系

发行包默认使用空的 `configs/topics/reference_taxonomy.json`，不绑定新能源领域。新能源本体仍保留为可选示例。上传其他领域的参考 JSON 后，新建轮次实际使用上传体系，并在轮次目录保存 `reference_taxonomy.json` 快照。点击上传区的“移除当前参考体系”可移除当前构建参考；原文件与配置归档到当前项目的 `data/reference_archive/日期-编号/`，新轮次从空体系开始。历史轮次、已发布版本、原始语料和上传原件不删除。正在加工时先停止任务再更换参考。参考 JSON 使用“参考文件中心/模板/参考话题体系.json”的 root/children 结构和 taxonomy_version、classification_object 字段。


### 标注查询、领域统计与来源筛选

检索页增加领域术语频次、正式话题体系和来源筛选。已保存项目标注无需BCC索引即可查看；只读分享限定为所分享的发布版。支持报刊、新闻、论文、政策文件、教材（精确到书名），未确认来源保留为未分类。新增 annotations、terms、topics、sources API，完整登录、调用、来源登记示例见 [检索与标注API使用说明](docs/检索与标注API使用说明.md)。旧版本缺少范围索引会明确拒绝来源限制，不回退成全库查询。

### BERTopic 聚类结合参考话题体系

上传参考体系后，新轮次会冻结该体系。完成 BERTopic 聚类后，可以选择“按参考体系命名并发布草案（无外部大模型）”：优先复用已保存的机器匹配证据，旧轮次缺少证据时使用话题名称、典型词与聚类代表内容做保守匹配；匹配成功保留参考体系的话题名称、层级与典型词，证据不足或候选并列时显示“待确认聚类”。这条路径无需外部大模型审核，仍标记为未审核草案；不覆盖正式体系或既有发布版。需要更换参考体系时请上传后建立新轮次。已批准的完整体系也可点击“直接复用已批准参考体系（不聚类）”。

### 项目存储额度

在项目根目录 `.env` 设置 `PORTAL_PROJECT_QUOTA_GB=100`（单位 GiB）后重启平台。新安装配置示例为100 GiB；未设置时兼容原来的10 GiB默认值。额度统计每个项目全部文件，包括原始语料、模型结果、索引和历史版本，不能代替磁盘空间检查。只限制实际上传的 POST 请求，查看已上传资源不受此额度拦截。额度不足会显示已统计占用、上传量、上限及配置字段；无需删除科研数据。目录统计在后台线程执行，避免阻塞门户响应。

参考匹配现支持典型词45%权重、术语ID与当前参考体系重连及缺少术语关联时的权重重分配。聚类完成但未启动审核/发布时，可在话题工作台点击“仅重算参考匹配（不重跑聚类）”；会备份原匹配并展示聚类/非离群样本句两种覆盖率，操作说明见 [话题体系构建指导](docs/话题体系构建指导.md)。

### 检索页术语长度与三级话题展示

领域术语卡片先筛选长度至少4个字符的术语，再按频次取前十；空白字符不计长度，汉字、字母和数字均计字符。完整术语频次CSV下载保留全部长度，沿用当前来源及查找条件。API `/api/v1/terms` 及 `/api/v1/terms/export` 支持 `min_length=4`；默认0兼容原接口。

检索页领域话题体系仅展示三级话题，标志词直接显示在名称下方，展开可看定义、完整路径和标注数；内部一级二级父节点仍保留，以维护完整体系和分类关系。API `/api/v1/topics?level=3` 可取得同样结果，默认 `level=0` 返回完整体系。标志词读取该版本已保存的 keywords/representative_keywords，旧测试簇可恢复标签内已保存的代表词；不从其他版本混入词语，缺失时明确提示补充后重新发布。当前项目V3的297个三级话题均有已保存的标志词。

### 在网页设置监听与分享地址

使用已授权账号登录“我的语料库”，点击右上角“访问与分享设置”；分享检索窗口也提供同名按钮。可填写 API_HOST、API_PORT、PORTAL_PUBLIC_URL，页面分别显示当前生效值与已保存值。保存只更新项目根目录 `.env` 的这三个字段，保留数据库密码、模型密钥和其他配置，并在 `logs/network-settings-backups/` 保存原配置备份；该目录含私有配置，不能分享或提交Git。

保存不会立即改变监听、分享链接或停止任务。等加工结束后，从原启动窗口关闭平台再正常启动；重新复制分享链接。监听0.0.0.0允许网络连接，但对外URL必须使用对方实际可访问的IP/域名，不能写0.0.0.0，不能包含 `/share/...` 路径。防火墙、校园网隔离和服务器反向代理仍需由管理员按部署环境设置。系统/启动器环境变量若有同名配置，其优先级高于.env。

首次授权由主机维护者在项目根目录运行 `python -m corpus_platform portal allow-network-admin 账号名`，重启后该账号可见设置入口。撤销时追加 `--remove` 并重启。名单存于 `PORTAL_NETWORK_ADMIN_USERS`，默认没有账号具备此权限；普通账号、未登录者与分享访问者均不可读写此设置。网页不能修改管理员名单。此授权仅管理访问与分享配置，不改变其他用户项目的所有权。

### 双击打开公开语料站

Windows 可双击根目录 `启动公开语料站.cmd`。它优先使用 `data/public_site/settings.json`；如果还没有配置，则打开空白示例站。检测到本机 8002 已运行公开站时直接打开网页，不重复启动；其他服务占用端口时提示错误，不停止任何进程。

首次启动后保留启动窗口，关闭网页不会停止服务；需要停止时在启动窗口按 Ctrl+C。重复双击只打开网页，可以关闭该次快捷入口窗口。Python 选择沿用加工操作台的环境发现机制；环境无法自动找到时，激活 `corpus-platform` 后运行，或设置 `CORPUS_PYTHON` 为自己的 Python 路径。

### 术语清洗与完整话题树

检索页按一级、二级、三级树状展示完整话题体系。新能源术语可离线清洗并保留原参考得分、排除与存疑记录；规范化资源保持编号并与旧发布版分开保存，详见 [术语清洗与话题规范化](docs/术语清洗与话题规范化.md)。

上传基础语料时可选择“政策文件”，用于政策、通知、办法等文本；来源登记、检索筛选与API使用同一类别。政策文件不要求填写教材书名，上传格式仍为TXT或含TXT的ZIP。已有文件可在当前项目来源登记中补录；旧发布版本保持原分类，新发布版才冻结更新后的类别。

模型API地址需与成功调用示例的完整路径对应，例如基础地址为`https://models.example.org/llm/v1`时请求`/llm/v1/chat/completions`。清洗提示词测试会明确显示上游HTTP状态及脱敏路径，避免接口404被笼统显示成500；说明见 [步骤模型配置](docs/步骤模型配置与项目命名.md)。
