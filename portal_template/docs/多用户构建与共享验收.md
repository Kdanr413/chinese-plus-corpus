话题体系采用现有“测试捷径”，没有替代正式多模型审核。句法步骤使用验收工具启动的本机 HTTP 测试接口，返回合成树；只验证接口、导出、索引与权限链路，不验证语言学句法质量。该接口只对验收子进程生效，不修改正式服务的句法配置。

匿名检索应命中本用户完整词项 270 次、另一用户完整词项 0 次；还检查匿名写入被拒绝、链接撤销后不可访问、另一账号不能打开项目。两组完整加工依次执行；没有证明两用户同时运行模型加工时的资源稳定性。

BCC 按词项和检索表达式查询。例如术语“甲组专用电芯”作为完整词项时，输入“甲组”不代表子串查找，应先用完整词项查询。

## 如何复现

管理员在项目根目录、已安装依赖的主 Python 环境中执行：

```powershell
$env:CORPUS_PORTAL_ACCEPTANCE='1'
python scripts/verify/portal_acceptance.py
Remove-Item Env:CORPUS_PORTAL_ACCEPTANCE
```

前提是 PostgreSQL 可用、干净模板存在、话题环境已安装 BERTopic 等依赖，并且本机已有 `BAAI/bge-small-zh-v1.5` 模型缓存。工具强制离线模型加载，不自动下载权重，不调用付费模型。它会新建随机临时账号、项目及数据库 schema；正常完成或异常退出时清理本次数据库记录和进程。强制结束整个 Python 进程可能绕过清理，因此应让工具自行结束。

生成的文件保留在 `data/pa/projects/<项目编号>/`，报告为 `data/pa/acceptance-<运行编号>.json`，不会进入普通用户项目列表。报告状态为 `passed` 才表示本次检查全部通过；失败时保留错误和已完成步骤。这些是验收资产，不应当作正式研究成果。

Windows 下请把主程序和 `PORTAL_STORAGE` 放在较短路径；本次修复缩短了编译缓存路径，但术语、轮次及原生工具仍可能受到深层目录和文件名长度限制。

## 原生隔离回归
