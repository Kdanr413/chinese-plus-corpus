# 术语识别与验证

## 目标

从每个完整句子或对话话轮中识别领域术语，形成可下载术语表，并把实际出现的术语写入逐句标记。

## 输入在哪里

- 清洗语料：`data/processed/corpus/`；
- 领域词表和已有术语：`inputs/linguistic/`；
- 本地识别配置：`configs/term_recognition/`；
- 正式话题体系：`data/curated/topics/taxonomy.json`；
- 外部模型和提示词：页面临时配置及 `configs/prompts/recognition/term_sentence_extraction/`。

已有术语表可以为空，系统仍能执行基础识别。

## 当前流程

1. `term_engine.py` 对全量句子/话轮执行分词、词性、领域语法、边界和通用词风险检查；
2. 形成带原句、位置、来源方法和证据的术语基础候选；
3. 未启用外部模型时，基础候选直接进入最终术语汇总；
4. 启用外部模型时，每个模型独立读取完整句子/话轮并返回术语集合；
5. 系统计算“基础候选 ∩ 模型逐句结果”，保留每个模型的原始反馈；
6. 按配置的多数、加权或全体一致策略聚合；
7. 可选交叉检验再用术语语境复核话题，但不会凭空增加基础候选之外的术语。

模型自报的置信度不是 Precision、Recall 或 F1。真正效果需要人工 Gold Standard 单独评价。

## 人工检查标准

如果需要人工抽检，应查看：原句、候选词、字符位置、识别方法、模型意见和话题路径，并判断：

- 是否构成稳定语言单位；
- 是否有明确领域意义；
- 是否只是普通高频词；
- 边界是否完整；
- 规范形式是否合理。

人工修订应追加保存，不覆盖机器原始证据。

## 输出在哪里

- 术语候选：Recognition Workspace 的 `02_term_candidates/`；
- 模型验证：`03_term_validation/`；
- 最终逐句标签：`08_approved_resources/sentence_labels.jsonl`；
- 正式术语表：`data/curated/terms/terminology.csv`。


## 最终术语表的得分列

加工页“下载最终领域术语表（含得分）”的 `score` 为术语基础识别的提取得分，不能当作外部模型置信度或人工准确率；模型检验一致性另见阶段明细的 `agreement_score`。基础识别分数可能达到上限 1.0，多个术语同分不表示模型重复运行。

同一规范术语在多条语句中出现时，最终表采用已批准候选中的最高有效得分，并保留稳定术语编号。0 是有效分数，不会当作缺失。历史最终表漏存分数时，下载接口使用对应识别轮次保存的 `05_term_validation/term_validation_table.csv` 按规范术语精确补齐，取可用分数中的最大值；不跨项目或轮次匹配，不新增术语、不调用模型。历史原表不会被覆盖，独立生成 `08_approved_resources/terminology_with_scores.csv`。

下载列 `score_source` 说明分数来源（`saved_terminology`：最终表已保存；`saved_term_validation_max`：从该轮次明细补齐）；`score_status=available` 表示有分数。若历史证据确实没有记录，例如人工新增词没有基础提取得分，保持空白并标记 `not_recorded`，不会伪造 0 分。
