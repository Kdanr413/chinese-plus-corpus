# 步骤模型配置、测试与项目命名

## 先配置、分别选择、测试后使用

1. 在项目页面“外部模型库”填写模型配置名称、模型 ID、接口地址、API Key 和权重。多个步骤可以共用一个模型，也可以选择不同模型。
2. 第 1 步清洗：单独启用大模型，明确选择一个清洗模型。系统使用该模型复核规则清洗的副本；不会自动取模型库第一个模型。
3. 第 2 步话题体系：仍在话题工作台中配置、测试及运行自己的话题模型，保留原有审核与发布过程。
4. 第 3 步术语识别：选择基础表直接输出，或选本步骤的一个/多个模型与基础表逐句取交集；单独配置策略、权重和最少有效模型。
5. 第 4 步交叉检验：单独决定是否执行、是否使用外部模型，并选择本步骤模型组与策略。不使用外部模型时运行基础一致性检验；整体关闭时跳过这一检验。术语不使用模型时，交叉检验仍可独立使用模型。
6. 点击“保存模型与步骤配置”。在各步骤下方打开提示词测试，使用本步骤输入测试。编辑提示词后，先保存为正式版本再测试；只有匹配正式提示词及已保存模型选择的成功测试才显示“已测试”。
7. 开始完整加工，系统读取已经保存、测试通过的各步骤配置。修改所选模型、接口、密钥、权重、策略、最少有效模型或正式提示词，会使相应测试失效；未通过测试会在调用加工模型前拦截。

配置在用户项目的 `configs/llm/step_models.json`，包括私有模型凭据和测试指纹。刷新网页或重启服务后可重新读取。不要将此文件提交 GitHub或随公开源码分享；源码打包工具会排除它。备份项目时将其作为私有配置保护。话题模型继续使用话题工作台自己的配置文件。

测试验证连接、返回格式和当前配置匹配，不保证所有实际语料识别都正确。测试和正式加工可能调用使用者配置的模型接口；用自己的模型按实际需求测试。

接口地址既可填写服务基础地址，也可填写以 `/chat/completions` 结尾的完整地址；清洗测试、清洗模型复核及术语/交叉检验调用只会追加一次该路径。接口域名仍需在平台的 `PORTAL_LLM_ALLOWED_HOSTS` 中获准使用，修改服务器允许域名后需要重启平台。

Windows 多用户项目目录较深时，长标题可能导致生成文件路径过长。清洗输出会按完整目录长度缩短文件名中的标题，保留文档编号以区分文件；完整标题、原始路径及正文保存在清洗文件和元数据中，原始上传文件不会因此改名。

完整加工的大模型清洗复核不再限制为 25,000 条，使用 `--limit 0` 处理所有未完成任务。命令行仍可设置正整数限制单次执行数量。已经启动的旧进程保持其启动参数，更新源码不会改变其内存中的上限，也不会中断当前调用。

登录会话已取消按时长自动过期，主动退出或账号停用后仍会失效。浏览器 Cookie 不设固定到期时间；浏览器关闭或清除 Cookie 后可能需要重新登录。修改前已到期的会话不会自动恢复，需要在更新服务后重新登录一次。若状态查询返回 401，后台加工不会因此停止；在新标签页重新登录，再刷新项目页面恢复查询。不要通过“开始新一轮加工”恢复状态。页面保留操作记录；状态数据缺失时会停止页面轮询，避免访问不存在的进度字段。

当前“暂停/继续”按钮控制识别流程，清洗子进程的系统挂起需由管理员执行。管理员挂起清洗复核后，可在该项目 `data/processed/cleaning_llm/pause_status.json` 写入 `status: suspended`、`paused_at`、`successful_records` 和 `total_tasks`，页面通过项目内预览接口显示暂停与已保存回复数量，不把暂停误认为任务完成。恢复进程时必须同步更新或删除此暂停状态文件，避免继续显示旧暂停记录。新一轮任务不会应用早于其启动时间的旧暂停记录。

`run_validation_llm.py` 支持断点续跑：使用相同任务文件和回复文件，不传 `--reset`，就会保留已有回复并跳过成功的任务编号；失败或未执行的任务会继续处理。续跑必须等原进程结束，不能同时向同一回复文件写入。还需保持任务顺序、模型和正式提示词一致；完成模型复核后再执行 `llm_clean_review.py apply` 安全应用建议。网页“开始新一轮加工”会重新生成任务并清空本轮模型回复，不应用于恢复旧进度。原始上传语料始终保留。

## 模型失败容错与针对性重跑

清洗复核、术语逐句提取、术语验证、交叉检验和话题独立审核按条目处理。超时、接口错误、空返回、无效 JSON 或校验失败会记录问题，继续处理其余条目。识别验证失败保持“不可用/待复核”，不会把缺少模型输出误当成术语被模型拒绝。网络/输出异常有有限重试；测试按钮只处理单个测试，仍明确显示失败。

失败请求保存在当前项目 `data/model_errors/`，包含输入快照、模型、错误、条目定位、尝试次数及重跑状态，不保存认证密钥。加工页侧栏“模型失败条目 / 重跑”打开 `/model-errors`：按对应服务选择失败项，临时输入 API Key 后重跑；已排队、运行或成功返回的请求不会重复提交。重跑成功保存返回结果，并在适用时补入标注缓存；原业务流程断点续跑仍负责结果校验和合并，不自动覆盖已发布成果。话题审核分支的“重跑失败项 / 继续运行”会直接跳过成功聚类、重跑失败或未完成聚类。

也可在项目根目录执行 `python -m scripts.workflow.model_errors --project .` 查看最新失败记录，使用 `python -m scripts.workflow.model_errors --project . --retry 错误编号` 重跑一项，密钥通过隐藏输入提供。清洗批次可使用原任务和回复路径运行 `run_validation_llm.py --retry-failed --continue-on-errors`，不要加 `--reset`；成功回复按输入指纹跳过，失败项恢复后再由 `llm_clean_review.py apply` 安全应用。清洗报告保留失败数量与待复核任务编号。

新功能需要新启动的服务/加工进程加载。旧运行任务不会因改文件而热加载；有活动任务时不强制重启。新服务加载后错误重跑入口才显示。现有运行任务的失败结果仍保留在原话题分支或清洗回复文件中。

## Windows 长路径

清洗磁盘 I/O 使用 Windows 扩展路径（含 UNC 路径），覆盖原文读取、按来源输出、JSONL、元数据、模型清洗建议应用及报告写入。目录过深时不再单纯依赖截短标题来绕过传统总路径限制；已实测超过 280 字符的路径创建和写入。文件名仍按路径预算缩短，完整标题与原始路径保留在元数据中。扩展路径前缀仅用于 I/O，页面和语料元数据使用普通路径；文件系统单个目录/文件名的长度限制仍需遵守。

## 模型标注结果的长期保存与复用

每个项目的 `data/model_annotations/` 保存按请求指纹组织的模型输出；`runs/` 归档历史任务与模型回复。缓存留在用户项目中，不提交 GitHub，也不复制给其他账号的项目。备份项目时应同时备份缓存及历史任务。

清洗复核，以及术语提取、术语验证和交叉检验的兼容模型调用已接入缓存。请求指纹包括接口、模型、模型版本（识别模块）、温度、正式提示词、输出结构和输入内容。只排除文档、段落、语句和运行的定位编号；复用时将返回的定位编号字段映射到当前任务。正文、上下文、来源、参考体系及候选项保留在判断条件中。因此同一语句在不同上下文或参考体系下可能仍需调用模型，不能仅按语句文字盲目复用。无效 JSON 和失败请求不写入缓存；复用后的结果仍通过原有识别及清洗安全门禁。

新一轮清洗会先归档旧任务与回复，再生成任务；`--reset` 只重置本轮回复文件，重置前先归档，不删除长期缓存。断点续跑不再仅凭任务序号跳过，而是校验输入指纹，避免语句重排或配置变化后沿用错标。旧回复缺少指纹时不盲目认定序号匹配；需要按原任务、模型和正式提示词核对后导入缓存。现有暂停任务的历史回复已保留，当前正在运行或挂起的旧进程不会因更新代码而热加载新逻辑，新启动的进程使用新缓存逻辑。

清洗复核会逐条输出完成数量与缓存复用数量，页面进度不再只在失败时刷新。历史原始回复保留原样，新的复用记录包含 `cache_key` 和 `cache_reused`，便于核查本轮是否实际调用模型。

## 聚类防重复提交与资源释放

话题工作台“测试首个聚类”只测试接口与提示词，不启动批量审核。测试期间按钮暂时禁用，完成或失败后恢复。若模型未在配置的超时秒数内返回完整结果，页面显示模型读取/连接超时（HTTP 504）；上游接口错误显示具体原因（HTTP 502）。超时不能据此判定提示词或模型输出 JSON 格式错误，应先检查模型服务响应速度、服务地址和网络，再重新测试。

独立审核的“启动成功”和“页面资料刷新成功”分开处理：任务接受后立即显示并轮询进度，刷新失败不将已启动任务误报为未启动。状态查询临时失败时保留上次进度并重试；启动请求超时则只读查找已有任务，避免重复提交。门户响应超时显示“操作可能已被后台接受，请先查看状态”，不据此取消后台任务。页面初始资料加载失败时，可从项目内保存的任务记录恢复查询。登录失效或无权访问时停止重试，需重新登录。

语料来源统计按源文件修改时间、大小和输入规则缓存；源语料或规则变化后重新统计，正常状态刷新不反复预处理全量语句。模型批量审核仍每完成一个聚类保存结果和断点，单项失败会记录在该分支，不能把单项失败等同于整个任务停止。

关闭浏览器页面不会停止服务器后台任务。系统挂起只停止进程计算，不释放该进程已占用的显存；释放资源需要结束对应后台进程。管理员应先核实项目、轮次、进程编号和启动时间，只处理已确认的重复任务，并保留成功结果与原始语料。

聚类提交由后端加锁预约任务：同一轮次的重复请求返回已有任务，同一项目有排队、运行或暂停的聚类时不能再启动其他轮次。成功轮次复用已有聚类任务和结果，不覆盖历史成果；需要重新聚类时新建轮次。前端点击后立即禁用启动按钮，运行中及成功轮次不可再次点击。前端限制不能代替后端检查。

## 同一账号的项目名称

创建时按同一账号查重，忽略首尾空白、连续空白、英文大小写和全角/半角差异。已有同名时提示“已有同名语料库项目，请重新命名”，不会创建额外目录。不同账号可以使用相同名称。数据库通过账号事务锁和唯一索引限制并发重复创建。

现有项目不自动改名、合并或删除。名称校验不改变项目 UUID、存储路径或分享链接；原始语料和正式版本不动。历史重名记录保留，今后同名创建被阻止，需要输入另一个名称。
