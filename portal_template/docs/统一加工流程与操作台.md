# 统一加工流程与操作台

## 打开页面

1. 双击根目录 `启动语料库平台.cmd`，首次使用在启动窗口创建账号；密码为 3 至 128 个字符。
2. 访问 `http://127.0.0.1:8000/`，在登录页输入自己的账号和密码。
3. 在“我的语料库项目”新建或选择项目，点击“打开构建工作台”。
4. 项目内提供原有“语料库构建”和“语料库查询”，第 6 步发布区域提供“分享检索 / 管理链接”。

各用户只能访问自己的项目；账号由管理员创建，没有开放自行注册。增加账号或忘记密码时，管理员在主程序目录执行 `python -m corpus_platform portal add-user user02` 或 `python -m corpus_platform portal reset-password user02`，把示例账号替换成目标账号。

启动平台只会打开页面，不会自动创建加工任务。没有任务时页面显示“尚未启动”，必须由使用者点击“开始完整加工流程”。如果后台确实存在未完成任务，页面才会恢复并展示它的真实进度。

## 本文中的文件路径

本文所有 `data/`、`inputs/`、`configs/` 路径都相对于当前用户的项目目录。默认是：

```text
D:\production\corpus\data\portal\projects\<项目UUID去掉连字符>\
```

项目 UUID 可从工作台网址 `/p/<项目UUID>/` 取得。同一账号的不同项目也分别保存；文件夹不使用用户名，账号与项目归属保存在 PostgreSQL。

- 原文：项目内 `data/raw/manual/`。
- 话题各轮：项目内 `data/workspaces/chinese-plus/topic-workflow/workflow/rounds/`。
- 正式版本与索引：项目内 `data/releases/<corpus_id>/<version>/`。
- 构建日志：项目内 `logs/worker.log`；网页操作记录为 `logs/runtime/platform-operations.log`。

原主项目历史文件仍留在原目录，不自动分给新账号。详细文件表及备份方法见 [多用户说明](../corpus_portal/README.md#每个用户的文件保存位置)。

## 完成一次构建

### 1. 上传并选择文件

- 原始语料可一次上传多个文件；
- 点击“查看并确认已上传语料”，查看内容并勾选本轮范围；
- 未勾选文件不会进入本轮加工，也不会被删除；
- 参考话题、术语和分词资源可分别上传，原件在 `data/raw/reference_uploads/`，当前生效文件在 `inputs/` 或 `configs/topics/`。

### 2. 选择模型方式

- 本地基础流程：不需要模型账号；
- 单个外部模型：填写一套模型 ID、API 地址和 Key；
- 多个外部模型：逐个新增模型，并选择多数、加权或全体一致；
- 模型 API 地址须使用管理员在 `PORTAL_LLM_ALLOWED_HOSTS` 中允许的 HTTPS 域名。
- 各用户填写自己的 Key；原流程可能将其写入该项目运行配置，项目目录与备份应保持私有。

### 3. 语料清洗

系统处理本轮全部勾选文件。模型清洗只允许修复格式和能够由上下文唯一确认的 OCR 错别字，不允许润色或改写原文。

输出在 `data/processed/corpus/`，原文仍在 `data/raw/`。

### 4. 建立话题体系并标注全量语句

系统把记叙文拆为完整句子，把对话体拆为完整说话人话轮。它固定抽取全量有效单元的 `ceil(N/3)` 建立三级话题体系。

每次点击“开始完整加工流程”并完成清洗后，系统都会为本轮创建一个新的话题体系构建轮次。即使相同语料以前已经存在已发布体系，也不会跳过本轮构建直接分类。历史轮次只用于查看或在中断恢复时继续，不作为新流程的自动捷径。

话题弹窗依次完成候选发现、多模型独立标注、人工冲突裁决和发布。弹窗会自动定位到本轮新建的轮次。发布后，主流程才使用本轮发布并激活的话题体系标注全部单元。最终生效体系位于 `data/curated/topics/taxonomy.json`。

如只想测试后续流程，可在聚类完成后勾选“测试捷径”，直接把非离群 BERTopic 簇发布为测试体系。系统跳过模型匹配和人工裁决，路径统一为 `BERTopic测试体系 > 聚类结果 > 簇ID｜代表词`。它会临时成为平台当前体系，但不会改写正式 canonical taxonomy，不能用于正式成果。

从“开始完整加工流程”进入话题弹窗时，主页面会同时监听发布消息并轮询本轮发布状态。正式发布或测试直发成功后，系统自动关闭弹窗，使用当前生效体系对全部句子或完整话轮进行话题分类，然后继续术语识别、可选交叉检验和结构化。这里是“按既有体系全量分类”，不会再次对全量语料运行 BERTopic。

如果在项目内单独访问 `/p/<项目UUID>/topic-workflow`，页面没有完整加工任务的模型与步骤配置，因此只负责构建与发布体系。首页中的“从已发布话题体系继续全量分类”仅用于恢复已经中断的旧流程，不是新流程的默认路径。

如果体系已经发布、但旧页面没有成功启动后续任务，首页会显示“从已发布话题体系继续全量分类”。点击后会明确使用 `data/curated/topics/taxonomy.json` 中的当前生效体系（包括 BERTopic 测试直发体系），再按页面当前的术语模型和交叉检验设置继续；不会重新清洗，也不会重新运行 BERTopic。上传的参考话题表只用于建立体系，不会覆盖刚发布的当前体系。

全量分类启动后，系统先保存可追溯的句子/话轮识别单元。页面会显示“正在保存全量识别单元：已完成数/总数”，而不是长时间停在“读取语料”。刷新或重新打开首页时，页面会重新订阅当前后台任务；即使识别在页面关闭期间完成，重新进入后也会继续标签激活和结构化。已经完成结构化的同一任务会被记录，不会因刷新而重复执行。

### 5. 识别术语

所有单元先运行本地术语基础识别。未启用外部模型时直接采用基础结果；启用时，每个模型对完整句子或话轮识别术语，再与基础候选求交集。

最终术语表位于 `data/curated/terms/terminology.csv`。逐句证据保存在当前 Recognition Workspace。

### 6. 可选交叉检验

启用后，系统用当前句子的术语检查话题路径。如果模型建议的是正式话题体系中的合法路径，系统可修正并保存原路径、修正路径和理由。关闭时直接采用独立识别结果。

### 7. 标注、结构化和发布

结构化输出至少包含句子序号、来源、一级话题、二级话题、三级话题和术语标记。随后平台创建 Workspace、BCC 索引、Release 和数据库登记。

步骤 5 可设置“进入结构化标注的术语最低分”，范围为 0–1：

- 默认值 0，表示保留全部已通过术语，兼容旧流程；
- 分数低于阈值的术语仍保留在识别证据和术语表中，但不写入本轮结构化语料的 `#Group 术语=...` 标记；
- BERTopic 测试发布产生的“BERTopic测试体系 / 聚类结果”是流程包装名称，不作为一级、二级话题。测试体系只有一个真实聚类名称时，只写一个实际话题层级；正式三级体系仍按真实路径拆分。

Release 位于 `data/releases/<corpus_id>/<version>/`，同版本不会覆盖。

## 发布后分享给其他人

1. 完成第 6 步索引与版本发布。
2. 点击该区域的“分享检索 / 管理链接”，选择正式版本与有效期。
3. 生成并立即复制链接；也可以返回“我的项目”操作分享。
4. 接收者打开链接即可检索，无需账号。只能使用所选版本，没有上传、构建、修改或整库下载入口。
5. 在同一面板撤销链接后，后续请求失效。新版本需要另外分享，不会替换旧链接所指版本。

链接原文只在创建时显示，刷新后不会重新显示，遗失时可重新生成。分享继续读取所有者项目的正式版本，不把语料复制到访问者目录。服务、数据库和索引文件需保持可用；已保存到别人电脑的查询结果不会随撤销收回。

`127.0.0.1` 只供本机体验。他人从其他电脑使用时，需要网络可达的部署地址及对应 `PORTAL_PUBLIC_URL`。见 [服务器部署说明](../deploy/portal/README.md)。

## 暂停和重新运行

- “暂停”在当前安全处理单元结束后生效；
- “继续”从已保存状态恢复；
- 运行时按钮显示“停止当前任务并新建”，停止检查会在术语候选生成、边界检查、嵌套检查等长步骤中周期执行；
- 空闲时按钮显示“清空页面并开始新一轮”，只重置页面状态，不会自动启动加工；
- 停止任务不会删除上传原件、历史 Release 或审计记录；
- 页面刷新后会尝试恢复正在运行的任务；
- 如果输入文件或话题、术语、分词资源发生变化，结构化结果和索引会重新构建；内容与 checksum 都一致时才允许复用。

## PDF/OCR 空字符处理

PDF 或 OCR 转换文本偶尔会混入不可见的 `U+0000` 空字符。PostgreSQL 的 `text` 和 `jsonb` 不允许保存该字符。

- 原始上传文件保持不变；
- 清洗副本会移除 `U+0000`，并在元数据中记录 `nul_characters_removed`；
- Recognition 文档加载、句子/话轮分析单元创建、PostgreSQL 普通 `text` 字段和 `jsonb` 写入边界都会再次防御性清理；
- 该处理只删除不可见空字符，不修改其他正文、话题标记、术语标记或 Release 编码。

## 小黑窗运行记录

页面底部的小黑窗按照时间顺序记录本次浏览器会话中的运行操作和进度，包括上传与文件选择、提示词测试与保存、清洗、创建话题轮次、聚类、模型审核、人工裁决、正式或测试发布、全量识别、暂停/继续/结束、结构化和版本发布。

- 话题体系弹窗中的运行操作也会同步回主页面记录；
- 相邻的相同轮询状态会自动合并，避免刷屏；
- 刷新页面后仍保留本会话记录；点击“清空页面并开始新一轮”会清空旧记录；
- 日志只保存操作说明和状态，不记录 API Key、数据库密码、请求正文等敏感内容。

同一份安全日志也会写入 `logs/runtime/platform-operations.log`。双击 `启动语料库平台.cmd` 时：

- 如果服务尚未运行，启动窗口直接显示 FastAPI 输出和网页操作；
- 如果服务已经运行，启动窗口会打开网页并持续跟随上述日志文件；
- 按 `Ctrl+C` 只会停止查看日志，不会停止已经在后台运行的服务。

全量话题检验按每 250 条更新一次“已检验/总数”。系统使用 `document_id` 映射直接取得句子，避免在数万条语料中为每个候选重复顺序查找。

基础分词、术语候选登记、逐句标签写入、结构化 Item 生成、GB18030 文件写入和句法树生成都会按批次输出“已完成/总数”，页面进度条和运行记录会同步更新。批次进度属于可观测状态，不会改变加工结果。
# 检索来源与健康检查（2026-10-09）

检索例句突出显示所属话题、来源文件名称和句子序号。来源名称优先读取对应 Release 的 `metadata/selection.json`，旧版本没有清单时回退到已有来源标记；BCC 原始编号仍可展开查看。不会重建索引或改写已发布语料。

构建页左侧服务区提供“健康检查”（打开 `/health`）与“立即检查”。页面每 15 秒检测服务连接。连接失败、恢复及状态读取失败会写入“全流程运行记录”，断线期间记录保存在当前浏览器会话中。

运行阶段超过 3 分钟进度未变化时提示“待检查”，不是自动判定失败：服务响应正常不等于任务正在推进。请查看启动窗口与具体任务进度，不要重复提交任务。该提示不能替代后台各步骤的细粒度进度。

## 清洗与术语模型独立选择

“清洗使用大模型”单独勾选；开启后使用外部模型列表第一个模型，先执行规则清洗再调用模型复核并安全应用修正。关闭时只有规则清洗。术语方式另行选择：基础表直接输出，或基础表与模型逐句独立识别结果取交集。模型独有而基础表没有的术语不会自动新增。多模型按多数、权重或一致策略聚合，原始文件不改动。
