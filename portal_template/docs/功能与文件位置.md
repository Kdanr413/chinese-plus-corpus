# 功能与文件位置

这份表用于回答三个问题：功能在哪里实现、读取什么、结果去哪里找。

## 全流程索引

| 功能 | 主要实现 | 输入位置 | 中间结果 | 最终结果 |
| --- | --- | --- | --- | --- |
| 上传和选择语料 | `corpus_api/` | 浏览器上传；已有文件在 `data/raw/manual/`、`data/raw/web/` | 上传原件保存在 `data/raw/` | 本轮勾选范围由平台读取，原件不变 |
| 上传参考资源 | `corpus_api/` | 页面上传话题、术语、词典或分词文件 | 原件在 `data/raw/reference_uploads/`，登记表为 `upload_manifest.csv` | 规范化后的当前输入在 `inputs/` 或 `configs/topics/` |
| 语料清洗 | `corpus_pipeline/`、`scripts/prepare/` | 本轮勾选的 `data/raw/` 文件 | 审计在 `data/interim/cleaning_audit/` | 清洗副本在 `data/processed/corpus/` |
| 话题体系建设 | `corpus_topic_workflow/` | 清洗后的全量有效语句；参考体系来自 `configs/topics/` | `data/workspaces/chinese-plus/topic-workflow/` | `data/curated/topics/taxonomy.json` |
| 全量话题标注 | `corpus_recognition/` | 正式话题体系和全部句子/完整话轮 | 当前识别 Workspace 的 `04_topic_candidates/`、`05_topic_validation/` | `08_approved_resources/sentence_labels.jsonl` 中的话题路径 |
| 术语基础识别 | `corpus_recognition/term_engine.py` | 全部句子/完整话轮；辅助资源在 `inputs/linguistic/`、`configs/term_recognition/` | 当前识别 Workspace 的 `02_term_candidates/` | `data/curated/terms/terminology.csv` |
| 外部模型术语交集 | `corpus_recognition/term_intersection.py` | 基础术语候选、当前句子和页面临时模型配置 | 逐模型证据保存在识别 Workspace | 最终术语仍写入 `terminology.csv` 和逐句标签 |
| 话题—术语交叉检验 | `corpus_recognition/` | 已标注话题、已识别术语、正式话题体系 | `06_term_topic_cross_validation/` | 修正路径和理由写入逐句标签与决策证据 |
| 综合决策 | `corpus_recognition/decision.py` | 术语、话题和可选交叉检验结果 | `07_decision/` | `08_approved_resources/` |
| 结构化与句法树 | `scripts/workflow/stages.py` | 清洗语料、逐句标签、正式话题和术语 | `data/processed/index/` | `corpus_index_syntax_tree.txt` 及配套 JSONL/CSV |
| Workspace 与 Release | `corpus_releases/`、`corpus_platform/` | 结构化语料、元数据和可选索引 | `data/workspaces/<corpus_id>/<workspace_id>/` | `data/releases/<corpus_id>/<version>/manifest.json` 及资产目录 |
| BCC 索引 | `corpus_search/` | GB18030 兼容的 `corpus_index_syntax_tree.txt` | Workspace 中的 `index/` | Release 中的 BCC 原生索引、`Org.txt`、`Org.dat` 和范围索引 |
| 数据库登记 | `corpus_registry/` | Release 的 manifest、相对路径和 checksum | PostgreSQL transaction | `corpora`、`corpus_versions`、`corpus_files` 等管理表 |
| 查询与导出 | `corpus_api/`、`corpus_search/` | Registry 指向的 Release 与 BCC 索引 | 只读查询，不改 Release | 浏览器显示；用户主动下载 JSON、CSV 或结构化文件 |

## 一个识别任务内部有什么

每次识别任务位于：

```text
data/workspaces/chinese-plus/recognition_<时间>/recognition/
```

| 子目录 | 内容 |
| --- | --- |
| `01_preprocessed/` | 标准化文档、句子和对话话轮 |
| `02_term_candidates/` | 术语基础候选和来源证据 |
| `03_term_validation/` | 各模型术语意见和聚合结果 |
| `04_topic_candidates/` | 全量语句话题候选 |
| `05_topic_validation/` | 话题验证证据 |
| `06_term_topic_cross_validation/` | 可选交叉检验和话题修正 |
| `07_decision/` | 综合决策 |
| `08_approved_resources/` | 逐句最终标签、术语表和可发布结果 |

## 页面下载入口

- 话题体系：话题工作台发布后，在“话题与术语成果”下载。
- 术语表：术语识别完成后，在“话题与术语成果”下载。
- 结构化语料：完成“语料标注与结构化”后下载。
- 查询结果：在“语料库查询”页面保存为 JSON 或 CSV。
- API 用法：服务启动后访问 `http://127.0.0.1:8000/docs`。

BERTopic 测试直发文件保存在对应轮次目录的 `bertopic_test_taxonomy.json`，快照在话题工作区的 `taxonomy_snapshots/`。它只用于流程测试，不替代正式 canonical taxonomy。

## 不要手工修改的位置

- `data/raw/`：原始资产只增不改；
- `data/releases/`：正式版本禁止覆盖；
- `data/processed/`：自动结果应通过重新运行生成；
- BCC 索引文件：只能由 `corpus_search` 构建；
- `db/migrations/` 已执行的 SQL：只能新增更高编号 Migration；
- `.env` 中的密码和模型密钥：不得写入说明文件或 Git。
