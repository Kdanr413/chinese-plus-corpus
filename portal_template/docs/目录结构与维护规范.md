# 目录结构与维护规范

当前唯一项目根目录是 `D:\production\corpus`。迁移后，以包含 `configs/pipeline.json` 的目录为新根目录。

## 目录职责

| 位置 | 内容 | 维护规则 |
| --- | --- | --- |
| `corpus_api/` | FastAPI、网页、上传、查询和导出 | 调用公共模块，不复制算法 |
| `corpus_pipeline/` | 清洗和结构化公共接口 | 页面、命令行和任务共同调用 |
| `corpus_topic_workflow/` | 话题体系候选、机器标注、人工裁决和发布 | 正式体系发布到 curated |
| `corpus_recognition/` | 话题全量标注、术语、验证、交叉检验和决策 | 每步保留证据 |
| `corpus_search/` | LangSC.BCC 索引和查询适配 | 不重写 BCC 算法 |
| `corpus_releases/` | Workspace 和 Release 生命周期 | 不覆盖 Release |
| `corpus_registry/` | PostgreSQL 管理数据 | 不保存正文和索引内容 |
| `corpus_platform/` | 统一诊断、加工、发布、验证和启动 | 只编排其他模块 |
| `configs/` | 规则、阈值、提示词和路径配置 | 不保存密码 |
| `inputs/` | 当前生效的人工参考资源 | 页面上传或管理员维护 |
| `data/` | 原件、中间结果、正式成果、Workspace 和 Release | 按生命周期管理 |
| `scripts/` | 底层算法和兼容脚本 | 普通用户不直接运行 |
| `tests/` | 自动化测试 | 功能变化同步更新 |
| `docs/` | 当前操作、验收及维护指南 | 从 `docs/README.md` 进入 |

## 能否删除或修改

| 类型 | 示例 | 规则 |
| --- | --- | --- |
| 永久资产 | `data/raw/`、`data/releases/` | 默认不删除、不覆盖、不手改 |
| 正式参考 | `data/curated/` | 通过发布流程更新，不直接编辑 |
| 可编辑任务 | `data/workspaces/` | 可继续加工；不要冒充 Release |
| 可重建结果 | `data/interim/`、`data/processed/` | 无运行任务且确认不需审计时可重建 |
| 数据库结构 | `db/migrations/` | 只新增迁移，不修改已执行 SQL |
| 本机秘密 | `.env` | 只在本机保存，不提交、不展示 |
| 缓存 | `__pycache__/`、`.pytest_cache/` | 可删除，不是项目成果 |

## 路径原则

- 业务代码不得写死 `D:` 绝对路径；
- 项目根目录由代码位置或 `CORPUS_PROJECT_ROOT` 确定；
- 数据根目录由 `CORPUS_DATA_ROOT` 确定；
- 数据库使用 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`；
- Linux、Windows 和 Docker 只改变环境变量，不改变业务逻辑。

## 修改后的最低验证

1. 运行相关模块测试；
2. 运行 `python -m corpus_platform doctor`；
3. 涉及 Release 时先使用 `--dry-run`；
4. 涉及前端时检查页面和 JavaScript；
5. 不自动 commit、push 或部署公网，除非用户明确要求。
